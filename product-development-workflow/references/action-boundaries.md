# 动作与授权

在准备实施检查点、首次实施或执行有副作用的验证时读取。本文件细化[入口工作约定](../SKILL.md#工作约定)，不改变用户明确指令或宿主权限。

## 实施检查点

需求充分与实施获准分别判断。默认工作方式下，新开发任务的授权由以下对话建立：

1. 只读调查后给出当前理解、拟修改文件或边界、非目标、可观察验收结果，以及验证命令或方法和副作用。
2. 针对该范围请求实施与本地验证授权，说明当前尚未实施，结束本轮等待回复。
3. 用户后续回复明确指向该检查点，例如“按此修改并验证”。

阶段选择可以与检查点合并；计划确认也可以同时请求，但列清各决定。只回答需求问题、同意方案或批准文档，不等于批准实现。回复“确认”能否成立取决于是否唯一指向列明事项；多个独立待决事项下的含糊回复不扩大范围。

实施前说明采用的阶段、授权来源及覆盖范围。已有可复查的检查点与后续回复且仍覆盖本任务时直接复用，完成范围内修改、适用测试、修复及验收，不因换轮次或进入阶段七重复询问。用户明确变更确认方式时遵循其指令并记录依据，不机械强加第二次批准。

权限只覆盖用户实际同意的结果、文件或边界、动作、验证和副作用。新增范围只补齐新增授权，不冻结可独立继续的已授权工作。仅因文件名相同、计划已保存或过去做过类似任务，不能推定覆盖。

## 验证副作用

先读取项目配置判断真实影响；命令叫“检查”或“测试”不代表只读。

| 动作 | 所需范围 |
| --- | --- |
| 读取、搜索、比较已有文件、差异和日志 | 安全只读范围，可直接进行 |
| 构建、测试、依赖恢复、服务启动、临时报告与缓存 | 可复查的本地验证授权，涵盖命令或明确等价动作、目标、位置、启动停止和遗留状态 |
| 更新快照、锁文件、受版本控制的生成物或正式报告 | 覆盖这些目标的工作区写入授权 |
| 数据库、远程服务、生产数据、线上验证或其他真实外部状态 | 明确目标、影响和边界的对应授权 |

一个动作有多种副作用时同时满足各项覆盖。可以安全拆分则先做已授权部分；无法确定影响时先调查，仍不确定则指出具体缺口。

本地验证授权涵盖同一命令、目标、范围和副作用下，为本次修改修复与重跑的必要循环；不因一次失败重复请求。引入依赖、扩大目标、增加服务或改变副作用时重新判断覆盖。达到所需验证后停止，只有变化、失败或未解决疑点才扩大测试。

动态诊断的授权仅覆盖复现及约定的临时产物，不能据此修改项目源码或实施修复。用户明确只读或禁止运行时，说明静态证据的限度。

授权复用与结果复用分别判断；[阶段七](verification-and-acceptance.md#既有验证证据的复用)检查旧结果是否仍支持当前结论。没有授权的动作标为未执行，不能冒充失败或通过。

## 决定与评审

不同选择会改变用户可见结果、业务规则、权限或数据范围、公共契约、兼容、安全、隐私、显著成本或验收时，说明取舍并由用户决定。已有明确委托且涵盖该取舍时沿用；“按最佳实践”不能代替尚未确定的业务意图。

内部实现细节可自主选择，前提是位于已确认范围内、可逆，不改变上述结果或外部状态。代码现状、测试默认值和代理建议不自动成为需求。

涉及跨模块行为、公共契约、权限、安全、数据迁移、不可逆状态，或由其他代理实施时，在宿主支持并允许时使用独立评审。其他任务由当前代理做明确的二次复核。无独立评审能力时说明替代复核及其限制，不能将自检冒称独立评审。

复用覆盖最终变更的有效评审，不因阶段切换重复评审；记录评审者、采用依据、被评审内容、覆盖范围、问题及复核结果。具体有效性由[阶段七](verification-and-acceptance.md#既有评审结论的复用)核对。

## 外部与仓库操作

需求、文档和本地实施的批准不推导提交、合并、推送、发布、部署、生产迁移、真实数据操作或发送消息的授权。用户已明确授权这些动作时依其范围执行；否则先完成授权内可审阅的结果，再请求缺少的决定。使用新工具、代理或工作区不改变这些边界。
