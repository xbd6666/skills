# 阶段五：编写实施计划

本阶段把已确认的 Spec，或无需新增技术契约的已确认需求，转为文件级实施计划；不补做信息已充分的上游阶段，不重新决定业务规则或实施变更。

跨阶段的只读、确认、授权和正式产物持久化规则见[入口的“公共契约”](../SKILL.md#公共契约)；本文件只定义阶段五特有的计划内容、追溯与交接门槛。

## 目标

让缺少当前会话背景的实施者也能按计划完成工作，并能从每项需求追溯到任务和验证证据。计划应具体到职责、文件、依赖和验证，但不要预写大段生产代码或用虚假精度掩盖未知项。

## 输入与分流

开始前至少具备：已确认的需求与验收标准、适用项目规范、可确定的计划产出路径，以及任务需要时已确认的 Spec。记录采用的上游修订，并按入口的[“产物修订与下游有效性”](../SKILL.md#产物修订与下游有效性)检查依据；不能只凭原来的“已确认”状态继续。

- 适用的 Spec 仍有会改变用户可见行为、权限、数据、公共接口或验收结论的未决项：回到阶段四；若源头是业务意图不清，回到阶段三。
- 满足入口[“直接进入阶段六”](../SKILL.md#直接进入阶段六)门槛时，不要为了流程强行创建独立计划。
- 计划的内容、状态和路径是否足以形成正式产物，按入口的安全持久化条件判断；未确定时先解决对应未决项，不得把未定内容伪装成正式计划。

## 信息状态

沿用入口[共用词表](../SKILL.md#信息与证据)，补充两类信息：**上游约束**是需求、适用 Spec、非目标与项目规范中必须保持的内容；**计划技术决定**是为形成可执行任务而确定、且不改变外部语义的技术细节。留给实施者的决定还须不影响任务边界或接口。

## 核心流程

### 1. 定向调查实施面

读取完成计划所需的最小仓库范围：项目规范、相关入口、相邻实现、测试布局、构建配置和已存在的迁移或接口模式。记录事实来源；不要把当前代码自动升级为未来需求。

### 2. 建立追溯关系

按入口[“需求追溯标识”](../SKILL.md#需求追溯标识)沿用已有编号；输入未编号时在本计划中补齐，并映射原始需求及验收标准。有 Spec 时为其行为增加 `S-1`，并为任务增加 `T-1`；没有独立 Spec 时可直接从需求追溯到任务。明确例如：

```text
R-1 → S-1（如适用）→ T-1/T-2 → V-1
```

每项上游需求必须至少由一个任务实现，并有可判断的验证方式。任务不能加入没有上游来源的功能；必要的内部支撑工作要说明其服务的任务。

### 3. 设计文件与职责

先列出预计创建、修改和验证的文件或模块，以及各自职责和相互接口。未知位置可以写明定位方法，不得虚构路径、类型或函数签名。

遵循现有项目结构。只有当前结构会阻碍本次正确实施时，才把相关重构列入计划，并说明必须保持的外部行为。

### 4. 拆分可验证任务

一个任务应形成可独立评审的结果；验证命令须有调查依据，不得猜测。任务包含：

- 需求与适用 Spec 标识、目标、前置任务及必须保持的约束；
- 创建、修改和测试位置，以及输入、输出和依赖接口；
- 实施步骤与适用的测试先行要求；
- 验证命令或人工证据、完成条件及回退点。

不要机械追求固定分钟数。配置、脚手架和文档应归入真正需要它们的交付任务；只有相邻结果可以被独立接受或拒绝时才拆开。

### 5. 安排顺序与执行方式

按依赖关系、影响范围和失败代价安排任务。修改同一文件、同一迁移链或共享状态的任务默认串行；只有文件和状态互不冲突时才标记可并行。

根据任务选择执行方式：

- 局部任务：当前代理直接执行；
- 多个紧密相关任务：当前会话分批执行并设置检查点；
- 多个边界清晰的独立任务：在宿主支持且用户未限制时，可建议使用独立子代理执行和评审。

执行方式只是建议，不得由此推导创建 worktree、分支、提交或外部变更的授权。

### 6. 自检并交接

逐项检查 Spec 覆盖、任务依赖、名称与接口一致性、验证充分性以及占位文本。计划发现上游缺口时先回退修正，不要把问题留给实施者猜测。修订已有计划时先按入口修订规则核对旧版留存；计划通过自身检查和适用审阅后即可作为后续实施依据，不要求受影响任务、评审或验证预先完成。

## 计划最小结构

删除不适用章节，不保留空占位：

```markdown
# [功能名称] 实施计划

> 状态：草稿 / 待审阅 / 可执行
> 修订：r1
> 上游需求与 Spec：[位置及采用修订，或可复查的对话交接；无独立 Spec 时说明原因]
> 依据有效性：有效 / 待复核 / 已失效

## 1. 目标、范围与全局约束
## 2. 当前实现与文件职责
## 3. 追溯矩阵
## 4. 任务、依赖与执行顺序
## 5. 验证策略
## 6. 迁移、兼容、回滚与运行约束
## 7. 计划技术决定、实施时决定和未决项
## 8. 执行方式与授权边界
```

## 交接门槛

进入阶段六前确认：

- 每项需求和适用 Spec 行为映射到任务与验证；任务输入、输出、依赖和完成条件清楚，适用的失败路径、迁移、兼容、回滚和非功能约束均已覆盖；
- 上游修订与采用依据已核对，差异有可复查的保留或更新依据；受影响任务、评审和验证的有效性、复核要求及原授权范围已记录；
- 无改变外部行为或范围的未决项，计划已自检并完成用户要求的审阅；
- 已取得入口要求的[实施授权](../SKILL.md#阶段六实施授权)，不能仅因计划已保存而进入阶段六。

## 输出契约

计划的创建、更新和对话产出统一遵循入口的[“阶段三至五产物的安全持久化”](../SKILL.md#阶段三至五产物的安全持久化)。保存后输出计划摘要、可点击位置、状态、追溯覆盖、计划技术决定、仍需决定、推荐执行方式和授权边界，不重复粘贴正文；尚未取得阶段六实施授权时停止在计划产物。
