# 阶段六：执行开发计划

在获准范围内完成计划或直接实施任务，产出经过自检和适用评审的变更，持续推进到阶段七。阶段六本身不宣告整体开发交付完成。

## 开始条件

有可执行且依据有效的计划，或符合入口的[直接实施条件](../SKILL.md#直接进入阶段六)。读取[动作与授权](action-boundaries.md)，能够指出当前阶段选择、修改及验证的授权来源。上游发生修订时按[产物有效性](artifact-contracts.md#产物修订与下游有效性)核对受影响任务。

缺少授权只停止对应动作；缺少信息回到拥有该决定的阶段。既有有效授权、规范和信息直接复用，不重复确认。

## 实施前基线与并行修改

首次写入前记录相关文件内容、已有暂存／未暂存差异和目标未跟踪文件；非 Git 项目保留等效内容或快照。优先用宿主和任务记录，不强制全库快照、清理工作区或新建账本。

每次编辑前核对目标与最近读取或写入后的状态。发现用户或其他代理并行修改时重新读取、保留其内容；无法安全合并则暂停该处。保留最初基线用于归因，不因重读把别人的改动算成本次工作。

## 执行与复核

按任务依赖执行，在既定范围内自主处理内部实现细节。遵循项目测试策略，使用能证明行为和适用边界的验证。需要新测试时验证真实结果，避免镜像实现；已有相关测试或检查足够时直接使用，不机械强制每项改动都先写测试。

任务完成后自检需求覆盖、范围、项目约定、失败与警告；发现本次问题即修复并重跑受影响验证。按[评审条件](action-boundaries.md#决定与评审)做独立评审或二次复核，分别判断规格符合性和实现质量。正确性、安全、规格遗漏等必须修复并复核；纯偏好不扩张范围。

任务记录可放在现有计划、宿主工具或对话，区分待开始、进行中、阻塞、已实施待评审、已评审；保留采用依据、基线、实际变化、验证命令与原始结果、评审覆盖和遗留项。简单任务用简短记录即可。由其他代理实施时提供完整任务和授权边界，不依赖其未获得的会话历史。

## 偏差与阻塞

| 发现 | 处理 |
| --- | --- |
| 范围内、不改变行为或验收的内部细节 | 记录判断并继续 |
| 任务边界、依赖或验证方式有误 | 回阶段五修订受影响计划 |
| 技术契约冲突或不可实现 | 回阶段四 |
| 业务规则、范围或目标需要重定 | 按入口回到三、二或一 |
| 环境、工具或依赖失败 | 在授权内尝试有依据的替代，保留失败证据 |
| 新增动作或外部影响超出授权 | 先完成可独立推进的部分，请求新增范围 |

不反复用同样输入重试，不静默缩小验收或改写上游决定。修订需重新核对相关授权和证据。

## 交给阶段七

正常交接：任务、自检与适用评审完成，必须修复的问题已复核，需求与授权范围一致，变更归因和证据可复查。按[自动衔接](../SKILL.md#阶段六到七自动衔接)直接读取阶段七，不停在“实现好了，是否测试”。

阻塞交接：确实需要新增授权或外部条件才能继续时，列出已做和未做、实际变更、失败证据、尝试结果、遗留状态及恢复条件。能够继续的授权内任务先完成；不要求受阻项目先获得通过证据再报告阻塞。

交接不要求重跑已有有效验证或重复评审；由阶段七核对。用户明确要求此处停止时按[每轮结尾](../SKILL.md#每轮交付与结尾)说明阶段六及未进行的验收，不声称完整交付。
