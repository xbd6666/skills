# 项目约定

## 目标

依据仓库证据维护简洁、可执行、可追溯的项目约定。保留真实项目形态、既有文档权威及有效规则，不把偶然实现升级为团队规范。

## 三种工作方式

| 工作方式 | 适用请求 | 是否写入约定文档 |
| --- | --- | --- |
| `检查现有约定` | 检查既有约定、冲突、缺口、漂移及需要清理的内容 | 否 |
| `制定约定方案` | 设计文档布局、规则范围和准确的变更清单 | 否 |
| `创建或更新约定` | 明确要求创建、更新、清理，或确认上一轮可唯一识别的方案 | 仅处置已解析且获准的约定文档 |

只问“是否需要调整或清理”属于检查；其余未要求写入的设计请求使用方案方式。更新默认保留原结构和文档语言，报告沿用交流语言；已明确的范围、决定和授权直接复用。

## 执行边界

- 在宿主指令和工具权限内，用户明确指令优先于本技能默认流程；范围内已授权工作持续完成，不重复请求相同授权。仅检查或方案仍保持只读。
- 文档写入只涉及已解析的 `CONVENTIONS.md`、`AGENTS.md` 及用户点名的约定类文档，不自动授权业务代码、测试代码、Git、数据库、部署或外部系统操作。验证权限独立，默认静态检查，已有具体验证授权继续有效。
- 生效条款须有已确认依据；一般写入授权不等于采纳候选、迁移权威或撤销有效规则。整文删除须明确授权。文档与实现冲突时保留未决状态，不自行裁决。
- 保护无关改动并脱敏证据。冲突、重叠修改或范围缺口只暂停必须一起完成的关联变更组，独立且已授权的工作继续。暂停时引用实际读取的本技能文件及具体条款，说明为何适用和需要的最小决定；区分明确要求与自己的解释。

## 按任务读取

单点核对或明确的局部修正，先确认适用指令，再读取目标内容和直接证据即可。当前会话已读且未变化的内容可以复用；范围、文档或继承关系变化时补读受影响部分。按需读取不免除适用规则，也不省略父规则变更对后代及引用的影响检查。

| 需要解决的问题 | 读取资料 |
| --- | --- |
| 范围、布局、文档策略或语言有歧义；替换、整文删除、范围扩张、暂停或验证权限需细化 | [references/request-contract.md](references/request-contract.md) 的相关章节 |
| 建立体系、完整审查、确认候选、清理既有内容或处理未来路径 | [references/discovery.md](references/discovery.md) 的相关章节 |
| 文档权威、模块布局、父子继承、规则覆盖或关联变更 | [references/inheritance.md](references/inheritance.md) |
| 多文档或规则语义变更、复杂清理、记录验证命令与交付证据 | [references/verification.md](references/verification.md) 的适用检查项 |

只在新证据要求时扩大读取和检查范围。检查可简短交付；完整检查和方案分别选用[检查报告模板](assets/检查现有约定报告.template.md)与[方案模板](assets/制定约定方案.template.md)的相关内容。方案给出准确文件清单和变更摘要后交付，不自行进入写入。

## 文件角色与模板

| 文件 | 角色 | 模板 |
| --- | --- | --- |
| 根级 `CONVENTIONS.md` | 仓库级边界、包或模块地图、共享命令、公共规则和文档权威关系 | [assets/根级.CONVENTIONS.template.md](assets/根级.CONVENTIONS.template.md) |
| 模块级 `CONVENTIONS.md` | 模块职责、局部扩展、显式覆盖、公共契约和验证方式 | [assets/模块.CONVENTIONS.template.md](assets/模块.CONVENTIONS.template.md) |
| 根级 `AGENTS.md` | 代理第一入口、根规则入口和模块文档路由 | [assets/根级.AGENTS.template.md](assets/根级.AGENTS.template.md) |
| 模块级 `AGENTS.md` | 当前模块的规则路由和高风险执行护栏 | [assets/模块.AGENTS.template.md](assets/模块.AGENTS.template.md) |

上述分工用于新建体系或已明确采用的范围，不改变既有权威。模板按证据选节，不补泛化规则、占位符或编写说明。路径、命令及代码标识符保留原文。

生成 `AGENTS.md` 时，保留按任务读取、已读且未变化内容的复用方式，以及范围、文档或继承关系变化时的补读条件；这些执行入口要求不随可选章节一起省略。

## 完成条件

已完成请求范围内可独立交付的工作，相关规则与引用一致，未采纳候选及受阻组明确保留。单点修正核对实际差异、直接证据和必要关联；其他变更按验证说明选择检查。相关检查通过后停止，仅在新增改动、失败或未解决疑点出现时扩大或重复验证。

交付结论、必要证据、实际变更、验证结果及未决事项；静态确认不等于运行通过。仅创建或更新方式可报告文档已变更，验证产物单独列明。

## 本技能维护

维护本技能时到源码仓库读取 `project-conventions/tests/README.md` 并选择相关行为场景。`tests/` 仅随源码维护，不安装到运行副本；常规约定任务不需要这些资料。
