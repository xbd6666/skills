# 项目约定

## 目标

为具体仓库生成简洁、可执行、可追溯的 `CONVENTIONS.md` 与 `AGENTS.md`，帮助人类和编码代理保持目录职责、架构边界、公共契约、命名、测试、工具和安全要求的一致性。

核心原则：先识别仓库真实形态，再为该形态建立约定。不要把所有项目强行解释为分层架构，也不要把偶然实现直接升级为团队规范。

## 三种工作方式

三种公开工作方式使用能够直接说明动作的名称：

| 工作方式 | 适用请求 | 是否写入约定文档 |
| --- | --- | --- |
| `检查现有约定` | 检查既有约定、冲突、缺口、漂移或可维护性问题 | 否 |
| `制定约定方案` | 设计文档布局、规则范围和准确的变更清单 | 否 |
| `创建或更新约定` | 按已解析范围创建或最小更新约定文档 | 仅写入已解析的约定文档 |

工作方式选择、已有文档策略和范围扩张检查见 [references/request-contract.md](references/request-contract.md)；每次使用本技能都先读取该文件。

## 不可破坏的边界

- `检查现有约定`和`制定约定方案`不修改约定或业务文件，默认只读发现；可执行当前会话已授权的验证，具体动作、环境和副作用按请求契约核对。验证产物单独报告，不改变工作方式或扩大约定文档写入权限。
- `创建或更新约定`只授权创建或更新已经解析的 `CONVENTIONS.md`、`AGENTS.md` 及用户明确点名的约定类文档，不授权修改生产代码、测试代码、Git 状态、数据库、部署或外部系统。
- 读取配置或记录证据时不得输出密钥、令牌、连接字符串、个人信息或生产敏感地址；证据只保留必要路径、字段名和脱敏结论。
- 现有文档与代码冲突时，不得默认文档过时，也不得默认代码违规；先把冲突列为未决事项。
- 先识别既有权威关系，不因使用本技能而迁移规则。在新建或已采用默认分工的范围内，`CONVENTIONS.md` 承载新增项目约定，专业工程文档保留各自权威主题，`AGENTS.md` 只提供有来源的执行入口；接入和迁移规则见继承说明。
- 保留工作区中的无关改动。若目标约定文档已有未归属的修改，先报告重叠，不覆盖用户工作。

## 工作流

1. 读取 [references/request-contract.md](references/request-contract.md)，记录用户已经明确的字段和需要通过发现推断的字段。
2. 按 [references/discovery.md](references/discovery.md) 选择单点检查或完整发现，区分明确规则、强制配置、重复惯例、例外、冲突和假设；只在证据要求时扩大检查范围。
3. 发现完成后最终解析工作方式、范围、布局、已有文档策略和输出语言。
4. 需要判断文档权威、采用或迁移分工、处理父子继承、模块布局或冲突时，读取 [references/inheritance.md](references/inheritance.md)；变更父规则前先检查受影响子级文档和规则引用。
5. 选择与工作方式对应的输出：
   - `检查现有约定`：按 [assets/检查现有约定报告.template.md](assets/检查现有约定报告.template.md) 选择相关内容；单点检查可直接给出结论、精确证据和覆盖边界。
   - `制定约定方案`：使用 [assets/制定约定方案.template.md](assets/制定约定方案.template.md) 的结构，给出准确文件清单和变更摘要后停止。
   - `创建或更新约定`：根据根级或模块级角色选择模板，只将已确认规则写为生效条款，实施最小、证据充分的文档变更。
6. 按 [references/verification.md](references/verification.md) 验证目标文档及受变更影响的子级文档和引用，并完成交付说明。

## 文件角色与模板

| 文件 | 角色 | 模板 |
| --- | --- | --- |
| 根级 `CONVENTIONS.md` | 仓库级边界、包或模块地图、共享命令、公共规则和文档权威关系 | [assets/根级.CONVENTIONS.template.md](assets/根级.CONVENTIONS.template.md) |
| 模块级 `CONVENTIONS.md` | 模块职责、局部扩展、显式覆盖、公共契约和验证方式 | [assets/模块.CONVENTIONS.template.md](assets/模块.CONVENTIONS.template.md) |
| 根级 `AGENTS.md` | 代理第一入口、根规则入口和模块文档路由 | [assets/根级.AGENTS.template.md](assets/根级.AGENTS.template.md) |
| 模块级 `AGENTS.md` | 当前模块的规则读取顺序和高风险执行护栏 | [assets/模块.AGENTS.template.md](assets/模块.AGENTS.template.md) |

模板表达默认文档分工，不能用来改写既有权威关系。模板只是结构引导，删除不适用章节，不得用泛化内容或 `TODO`、`TBD`、空占位符凑齐表单。面向用户的标题、字段和值按最终输出语言展示；文件名、路径、命令、配置键和代码标识符保留原文。

## 文档内容原则

- 每条规则应能回答“把什么放在哪里”“允许或禁止什么”“新增能力按什么步骤”“如何验证”。
- 规则必须指向真实目录、文件、类型、命令、配置或风险；没有证据时省略，或明确列为待确认事项。
- 候选规则的采纳条件见 [references/discovery.md](references/discovery.md)。一般写入授权不等于采纳尚未确认的候选；未采纳内容只列为不生效的待确认事项。
- 局部扩展与父级规则叠加；有效覆盖只改变明确列出的规则部分和适用范围，其余父级规则继续适用。
- 不重复 `README.md`、`CONTRIBUTING.md`、`ARCHITECTURE.md`、`.editorconfig`、`CODEOWNERS` 等文档已经权威维护的内容；在 `CONVENTIONS.md` 中标明权威来源并链接。
- 默认分工下生成的 `AGENTS.md` 保持短小，职责、规则提醒和验证入口均指向已确认来源，不借模板创建新政策。长期规则在其权威文档维护；既有 AGENTS 权威内容按已确定关系保留或经授权迁移。
- 混合仓库可以同时具有多个项目原型；只为风险高、职责独立或公共契约明显不同的模块创建局部文档。

## 完成条件

交付按请求复杂度说明实际适用的范围、证据、文件、验证结果和未决事项，不填充无关项目。单点检查允许简短交付；完整方案和文档更新按验证说明报告。只有`创建或更新约定`可以报告约定文档已变更，已授权验证的产物单独列明。

## 本技能维护

仅在修改本技能规则或模板时读取 [tests/README.md](tests/README.md)，使用其中场景检查相关行为。常规仓库约定任务无需加载回归资料。
