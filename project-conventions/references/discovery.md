# 证据发现

## 发现边界

优先使用用户明确提供的仓库或模块路径。仓库根可以由版本控制根、工作区配置、解决方案或工作区清单推断；无法唯一确定且会改变输出时，保留为未决事项。

默认只做无副作用读取：文件清单、文本搜索、文件内容、版本控制状态与差异、构建清单和配置键检查。不要在`检查现有约定`或`制定约定方案`中运行构建、测试、格式化、代码生成、迁移、数据库命令或真实外部调用。

大型仓库先做有界清单，再读取代表性文件。默认排除明显噪声和生成目录，例如：

- `.git`、`.svn`、`.hg`；
- `node_modules`、`vendor`、包缓存；
- `bin`、`obj`、`dist`、`build`、`coverage`；
- 生成客户端、编译输出、模型产物、大型数据集；
- 已由清单或配置明确标记的生成目录。

如果生成目录本身就是约定对象，只读取证明其角色所需的最小内容，并在覆盖范围中说明例外。

## 最小检查集

1. 列出顶层目录、项目或工作区清单、入口文件和测试目录。
2. 从仓库根到目标目录查找全部适用的 `CONVENTIONS.md` 与 `AGENTS.md`。
3. 读取与当前范围直接相关的 `README.md`、`CONTRIBUTING.md`、`ARCHITECTURE.md`、`.editorconfig`、`CODEOWNERS`、构建文件、包清单和配置结构。
4. 识别语言、框架、入口、公共契约、依赖方向、持久化、生成物、部署表面和稳定验证命令。
5. 记录抽样范围、未读取区域和无法确认的事实。

读取配置时优先记录文件路径、配置键和行为，不复制配置值。发现疑似密钥、令牌、连接字符串、个人信息或生产地址时立即脱敏。

## 证据分类

每条候选规则先分类，再决定是否进入约定：

| 类型 | 含义 | 可否直接形成规则 |
| --- | --- | --- |
| 用户明确决定 | 当前请求中已经确认的范围、边界或偏好 | 可以 |
| 既有权威规则 | 适用的约定、贡献指南、架构文档或强制政策 | 可以，但需检查是否与实现冲突 |
| 工具强制事实 | 编译、包清单、静态配置或生成机制实际强制的行为 | 可以描述为事实约束 |
| 重复惯例 | 多个代表性实现一致遵循的模式 | 只能作为候选规则，标明证据强度 |
| 例外或冲突 | 与主模式或文档不一致的实现 | 不得被自动提升为规则 |
| 假设 | 证据不足的推断 | 不得写成既定规则 |

仓库“碰巧这样写”不等于团队“要求这样写”。对重复惯例至少记录代表性路径、反例和置信度。只有一个样本时，不把它描述为稳定惯例。

## 文档与实现漂移

现有文档和代码不一致时，记录为以下之一：

- 文档声明、实现违反，责任未定；
- 实现已普遍迁移、文档可能过时，责任未定；
- 多种实现并存，尚无统一规则；
- 用户已明确裁决。

未获得用户裁决前，不通过修改文档或选择其中一方来掩盖冲突。

## 项目形态

项目形态允许多标签，不要求单选。常见证据及关注点：

| 证据 | 可能形态 | 主要关注 |
| --- | --- | --- |
| 前端框架清单、页面、组件、路由 | 前端应用 | 路由、状态、API 客户端、样式、可访问性、视觉验证 |
| 服务入口、端点、控制器、中间件、OpenAPI | 后端或 API | 契约、鉴权、验证、服务边界、配置、可观测性 |
| 明确的领域、应用、基础设施或适配器目录 | 分层架构 | 依赖方向、层职责、端口与适配器、持久化边界 |
| 多个应用、包或工作区清单 | Monorepo | 所有权、共享代码、跨包依赖、构建与发布边界 |
| 公共导出、包清单且无应用入口 | 库或包 | 公共 API、兼容性、示例、版本和依赖策略 |
| 命令、参数解析、终端入口 | CLI 或工具 | 参数、标准输出、错误输出、退出码、幂等性 |
| 数据、特征、流水线、模型或 notebook | 数据或 ML | 来源、阶段、实验、产物、复现、隐私 |
| 基础设施清单、容器、编排或工作流 | 基础设施 | 环境、状态、密钥、发布安全、生成文件 |
| 移动平台工程或跨端框架 | 移动应用 | 页面、导航、平台目录、权限、资源和发布配置 |
| 内容、站点生成器或文档配置 | 文档站点 | 内容结构、元数据、资源、发布和链接验证 |

使用具体清单、入口和目录组合判断，不使用 `app`、`api`、`src` 等单个通用名称直接定型。混合仓库应记录多个形态及各自证据。

## 布局决策

- **仅根目录**：小型、单一用途或共享规则足以覆盖的仓库。
- **根目录加模块**：多个应用、包、层或高风险模块拥有不同职责和契约。
- **仅模块**：用户只针对某个子目录，且不希望建立仓库级政策。

模块文档只在职责独立、公共契约不同、错误代价高或局部规则确实不同的地方创建。不要为每个文件夹机械生成一对文档。

## 发现记录格式

至少记录：

| 证据来源 | 类型 | 观察事实 | 反例或冲突 | 结论状态 | 规则影响 | 置信度 |
| --- | --- | --- | --- | --- | --- | --- |
| 路径或只读命令 | 用户决定/权威规则/工具事实/重复惯例/例外/假设 | 可复核事实 | 无或具体位置 | 已确认/候选/冲突/未决 | 写入、引用、排除或待确认 | 高/中/低 |

把观察事实与建议规则分开，避免在同一个句子中把推断写成事实。
