# 验证与交付

## 通用安全检查

- 确认最终工作方式、目标范围、布局、已有文档策略和输出语言。
- 检查版本控制状态或等价工作区状态，区分已有改动和本轮改动。
- 不输出密钥、令牌、连接字符串、个人信息或生产敏感地址。
- 记录未检查区域、抽样边界和无法验证的外部行为。
- 只有用户另行授权时才运行会生成产物或访问数据库、外部服务、部署环境的验证。

## 检查现有约定

使用 `assets/检查现有约定报告.template.md`，并确认：

- 没有创建或修改文件；
- 每个问题包含严重度、维度、精确证据、影响和可执行建议；
- 明确区分当前缺陷、潜在风险和可选改进；
- 文档间冲突与文档实现漂移分别报告；
- 没有把约定方案中的文件清单伪装成现状检查结论。

## 制定约定方案

使用 `assets/制定约定方案.template.md`，并确认：

- 没有创建或修改文件；
- 推荐布局有证据，替代布局说明取舍；
- 计划文件使用准确路径，且没有越过用户范围；
- 每条拟议规则标明证据类型和结论状态；
- 明确列出扩展、覆盖、冲突和未决事项；
- 结尾给出可唯一确认的创建或更新范围，不把约定方案当成写入授权。

## 创建或更新约定

写入后重新读取所有目标文档，并检查：

- 实际变更文件与最终请求契约一致；
- 不存在 `TODO`、`TBD`、模板占位符或含糊的“视情况而定”；
- 所有真实路径、文档链接、配置键、类型名和命令存在；示意路径被明确标记；
- 根级 `AGENTS.md` 能路由到适用模块文档；
- 模块级文档声明正确的父规则路径；
- 每个覆盖项指向存在的上级文档和主题，并包含理由及适用边界；
- `AGENTS.md` 没有创建长期规则或声明覆盖权；
- 不重复权威工程文档中易漂移的内容；
- 文档语言匹配最终请求契约，模板固定文本已完整翻译；
- 没有强迫仓库采用与证据矛盾的项目形态；
- 差异中没有无关文件、意外换行重写或用户已有改动。

如果引用稳定的验证命令，优先由清单、脚本或当前 CI 配置证明其存在。仅看到 README 中的一条旧命令时，把它列为待验证，不宣称可运行。

## 交付说明

最终回答至少包含：

- 最终请求契约；
- 创建、修改、计划或检查的文件；
- 主要规则、问题或变更摘要；
- 实际执行的验证及结果；
- 未执行验证及原因；
- 未决冲突、人工确认项和外部验证边界。

仅文档变更时，不把本地静态检查描述为构建、真实数据库、部署或运行时行为证明。
