# 验证与交付

## 通用安全检查

- 确认最终工作方式、目标范围、布局、已有文档策略、报告语言及各目标文档语言。
- 检查版本控制状态或等价工作区状态，区分已有改动和本轮改动。
- 不输出密钥、令牌、连接字符串、个人信息或生产敏感地址。
- 记录未检查区域、抽样边界和无法验证的外部行为。
- 按 [request-contract.md](request-contract.md) 复核已有验证授权；具体动作及副作用已覆盖时执行并记录结果，不重复索要相同授权，未覆盖时保留静态检查边界。

## 检查现有约定

按当前检查范围选择 `assets/检查现有约定报告.template.md` 的相关内容和下列适用检查项：

- 没有创建或修改约定及业务文件；已授权验证产生的文件已单独记录；
- 每个问题包含严重度、维度、精确证据、影响和可执行建议；
- 明确区分当前缺陷、潜在风险和可选改进；
- 文档间冲突与文档实现漂移分别报告；
- 全范围审查已枚举后代约定并区分已读取、仅发现和不可读文件，结论没有超出实际覆盖；
- 既有权威关系按证据判断，没有仅凭文件名套用默认分工；
- 检查局部扩展是否错误免除了父级要求、覆盖是否仍匹配当前上级规则，以及候选是否被当作生效条款；
- 本轮范围内的既有内容已按发现规则复核，处置建议有依据，失效结论未仅依据搜索不到或代码未遵守；
- 没有把约定方案中的文件清单伪装成现状检查结论。

## 制定约定方案

使用 `assets/制定约定方案.template.md`，并确认：

- 没有创建或修改约定及业务文件；已授权验证产生的文件已单独记录；
- 推荐布局有证据，替代布局说明取舍；
- 计划文件使用准确路径，且没有越过用户范围；
- 每条拟议规则标明证据类型、结论状态，以及确认依据或待确认点；拟采纳候选列出可唯一识别的内容及适用范围；
- 明确列出扩展、覆盖、冲突和未决事项；
- 覆盖以目标范围的当前有效规则为基线，暂停范围按关联变更组划分；
- 父规则变更已检查受影响子级文档和引用，必要联动修改及范围外文件已明确列出；
- 涉及权威迁移时列明主题、原权威、目标文档及原内容处理方式，没有把迁移混入普通更新；
- 拟清理内容列明原位置、处置、依据、承接位置（如适用）及语义和关联影响；规则撤销、权威迁移或整份文档删除的授权与普通删减分别核对；
- 结尾给出可唯一确认的创建或更新范围，不把约定方案当成写入授权。

## 创建或更新约定

变更前按 [inheritance.md](inheritance.md) 完成父规则变更及整份文档删除的影响检查，确认必要联动修改均在授权范围内；存在范围缺口时暂停该组变更。变更后重新读取保留或新建的目标文档及受影响的子级、引用文档，获准删除的文档核实已不存在，并检查：

- 实际变更文件与最终请求契约一致；
- 既有主题权威得到保留，实际迁移与已确认方案一致，专业文档未因新建 CONVENTIONS 而丧失权威；
- 生效条款均有“已确认”的依据；候选采纳记录可追溯到具体规则及适用范围，未采纳候选和未决事项仅在明确不生效的待确认区或报告中出现；
- 不存在 `TODO`、`TBD`、模板占位符、模板编写说明（含隐藏注释）或含糊的“视情况而定”；
- 作为现存事实或可用引用的路径、链接、配置键、类型名和命令已核实；本轮创建的约定文档及互相引用在交付后有效；
- 已批准未来路径标明实际创建状态、用途、范围、启用条件和确认依据；未创建路径未伪装成现存路径、有效链接或父约定来源，未启用要求未伪装成现行规则，也未据此创建未授权业务目录；示意路径明确仅为示例；
- 根级 `AGENTS.md` 能路由到适用模块文档；
- 模块级文档声明正确的父规则路径，或在核实不存在后声明“无”；未知父级未被当作无，其他适用来源仍保留；
- 局部扩展与父级规则同时生效，只有有效覆盖明确改变的规则部分和范围使用子级规则；
- 每个覆盖项的上级路径、主题、摘要、理由和边界均匹配有效继承链及来源的覆盖条件，没有跳过中间层已生效的覆盖；
- 仅重命名时已更新引用并保留覆盖语义；实际删除或内容变更已按继承规则分别处理，没有自动将覆盖转为扩展或删除；
- 受影响子级文档及规则引用已复核；必要联动修改已完成，或该组变更因范围缺口仍未写入，没有留下已知失效引用或无效覆盖；
- 默认分工下 AGENTS 摘要随来源的有效规则解释，未抵消合法覆盖；独立护栏有来源、范围和覆盖条件，不因措辞更严自动获得独立权威；既有 AGENTS 权威内容按已确认关系保留或迁移；
- 不重复权威工程文档中易漂移的内容；
- 清理前后的有效规则已对照：未获准改变的要求、条件、强度、例外及独立护栏仍完整，合并或迁移有可用承接位置；
- 已获准且证据充分的过时内容已处理，待确认及受阻内容仍保留并在报告中说明；中间状态按发现规则收尾，未来要求未仅因路径不存在而被删除；
- 删除或迁移后的目录图、路由、标题引用和读取链仍有效；整份文档删除与明确授权一致，没有遗失未获准撤销的内容；
- 清理未扩展到无关内容或生成未授权的归档文件，未把编写说明、清理过程或历史验证记录写成长期要求；准确且无新证据的内容未被无意义改写；
- 报告与各目标文档分别符合语言契约；没有因报告语言翻译现有文档或破坏多语言结构，文件名、命令等标识符保持原文；
- 没有强迫仓库采用与证据矛盾的项目形态；
- 差异中没有无关文件、意外换行重写或用户已有改动。
- 受阻变更组保持原状，独立已授权组可正常交付；部分完成未被描述为全部完成或整轮未修改。

## 验证命令的执行信息

记录可执行命令时，同时说明工作目录（相对仓库根）、必要运行时或依赖等前置条件、验证对象与范围、副作用或产物，以及证据来源和状态。AGENTS 引用权威验证入口，避免复制一份独立命令清单。

优先从清单、脚本或当前 CI 同时核对命令与执行上下文。只找到命令文本不能证明它能从仓库根运行或覆盖所有模块；关键前提不明时标为待确认。仅看到 README 中的一条旧命令时，把它列为待验证，不宣称可运行。

区分静态确认、实际执行通过、执行失败和未执行或受阻。静态确认只证明已核对的命令及上下文；执行结果另记具体命令、工作目录、覆盖范围和产物，不能用静态检查替代运行证据。

## 交付说明

单点检查可用简短文字给出结论、精确证据（含必要的证据类型和事实）、覆盖范围及实际操作结果，无需填完整模板。完整方案或文档更新按实际适用项交付：

- 最终请求契约；
- 创建、修改、计划或检查的文件；
- 主要规则、问题或变更摘要；
- 既有内容的主要处置、依据及语义影响；合并或迁移的承接位置、未处理的清理项及原因；
- 已采纳候选的确认依据、未采纳候选及其不生效状态；
- 实际执行的验证及结果；
- 验证命令的执行上下文及产生的文件，与约定文档变更分别记录；
- 受影响子级文档和引用的检查范围、联动修改结果及未验证区域；
- 未执行验证及原因；
- 未决冲突、人工确认项和外部验证边界。

仅文档变更时，不把本地静态检查描述为构建、真实数据库、部署或运行时行为证明。
