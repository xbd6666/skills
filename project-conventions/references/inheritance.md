# 文档继承与权威关系

## 接入已有约定

先识别仓库已声明的主题权威、作用范围和读取优先级，以及当前会话已适用的宿主指令。本技能的默认分工不能重排这些关系；仅使用本技能、检查现状或要求更新文档，不等于授权迁移规则。

既有 `AGENTS.md` 中的长期规则可以按原权威关系继续维护并被引用，不因其位置与默认模板不同就判为错误。权威不明或现有声明相互冲突时，报告未决关系，不仅凭文件名选择一方；已有明确裁决时直接沿用。

迁移需要明确受影响主题、原权威文档、目标文档、原内容处理方式和授权范围。创建缺失文档也不能自动转移既有主题权威。以下文件职责及父子继承规则用于新建体系或已明确采用该分工的范围；既有体系按已识别关系处理。

## 文件职责

- `CONVENTIONS.md`：维护长期、可复用的项目或模块规则，是约定规则的权威来源。
- `AGENTS.md`：告诉编码代理先读什么、当前范围负责什么、哪些执行动作风险高；引用已确认来源，不建立或覆盖长期规则。

其他工程文档继续维护其专业内容：

| 文档 | 典型权威内容 |
| --- | --- |
| `README.md` | 项目介绍、使用入口、快速开始 |
| `CONTRIBUTING.md` | 贡献流程和协作要求 |
| `ARCHITECTURE.md` 或 ADR | 架构背景、决策和权衡 |
| `.editorconfig`、格式化或分析器配置 | 工具可执行的样式规则 |
| `CODEOWNERS` | 实际审查或所有权配置 |

`CONVENTIONS.md` 应引用这些权威来源，不复制易漂移的细节。发现同一规则由多个文档维护时，在检查现有约定或制定约定方案时明确建议的唯一权威来源。

默认分工下，职责说明引用真实职责来源；命名、依赖、测试政策和跨任务适用的禁止动作等长期规则在权威文档维护，AGENTS 只保留来源及必要提醒，保持原规则的条件、范围和强度。来源不明的要求作为候选处理，不通过“应当”或“不要”占位符补造政策。当前任务的一次性授权边界只约束本轮执行，不自动持久化为仓库规则。

## 适用范围与读取顺序

针对目标文件，从仓库根到目标目录依次发现并阅读每一级适用的 `CONVENTIONS.md` 和 `AGENTS.md`。

- 父级 `CONVENTIONS.md` 默认适用于其全部后代目录。
- 子级 `CONVENTIONS.md` 可以新增局部规则；新增规则属于“扩展”，与父级规则叠加，不需要覆盖声明，也不免除父级同一主题的要求。
- 子级 `CONVENTIONS.md` 改变父级规则时属于“覆盖”，必须在“覆盖项”中显式记录被改变的部分和适用范围。未明确覆盖的部分继续继承，包括同一主题下的其他要求。
- `AGENTS.md` 的执行护栏按其声明范围适用于后代目录；更局部的 `AGENTS.md` 可以依据已确认权威来源增加或收紧护栏，不能放宽父级护栏，也不能覆盖任何 `CONVENTIONS.md`。

## 冲突处理

先按“接入已有约定”解析权威关系。对已采用默认分工的范围，再按以下规则处理：

1. 同一主题的父子 `CONVENTIONS.md` 冲突且子级有有效覆盖声明时，仅在明确覆盖的规则部分和适用范围内采用子级规则，其余父级规则继续适用。
2. 父子 `CONVENTIONS.md` 冲突但没有有效覆盖声明时，报告未解析冲突；在`创建或更新约定`中暂停受影响文档写入。
3. `AGENTS.md` 的规则提醒与已确定的主题权威来源不一致时，按该来源判断漂移，不静默删除内容；若既有权威或迁移状态仍未决，不先认定 `CONVENTIONS.md` 优先。
4. `AGENTS.md` 的执行护栏比 `CONVENTIONS.md` 更严格且两者可以同时满足时，同时遵守。
5. 执行护栏和长期规则无法同时满足时，采用更安全的停止策略，报告冲突并请求用户裁决。
6. 父级或子级 `AGENTS.md` 不得通过“覆盖项”解除另一份文档的限制。

读取顺序用于发现更具体的上下文，不等于“后读文件自动覆盖先读文件”。

## 有效覆盖声明

每个覆盖项至少包含：

| 字段 | 要求 |
| --- | --- |
| 上级文档 | 存在且适用于当前范围的 `CONVENTIONS.md` 路径 |
| 上级主题 | 可唯一识别的标题或规则主题 |
| 上级规则 | 被改变规则的简短摘要 |
| 当前规则 | 只在当前范围适用的新规则 |
| 覆盖理由 | 由模块职责、框架、公共契约或风险产生的具体原因 |
| 适用边界 | 覆盖生效和终止的目录或条件 |

验证时同时核对上级路径、主题、当前规则内容和适用范围，以及覆盖项记录的上级摘要、覆盖理由和边界；路径和标题仍存在不等于覆盖仍然有效。

| 上级变化 | 覆盖项处理 |
| --- | --- |
| 仅路径或标题重命名，规则内容与适用范围未变 | 更新引用，保留原覆盖语义，不改成扩展或删除 |
| 规则内容或适用范围变化，包括标题未变的情况 | 重新判断覆盖是否必要、理由是否成立、边界是否匹配；不能只更新上级摘要来掩盖语义冲突 |
| 规则实际删除 | 先查明是否已迁移或被其他规则承接；确实不存在对应上级规则后，再判断局部要求是否仍独立成立，决定转为扩展或删除 |

无法唯一定位对应规则或无法确定处理方式时，报告未决冲突，暂停受影响写入。重新分类或删除如果会改变生效规则，应明确变更含义并按请求契约处理，不因引用失效自动实施。

## 父规则变更的影响检查

变更父规则时，检查范围包括未列入写入清单的关联文档；只读检查不扩大写入授权。

1. 写入前比较拟议变更与原文，识别路径、主题、规则内容和适用范围的变化。检查适用后代目录中的 `CONVENTIONS.md`、`AGENTS.md` 及引用受变更文档或规则的约定文档；未显式引用某主题的子级文档也可能因继承而受影响。
2. 记录受影响文件、继承或引用关系、覆盖项是否仍有效、必要联动修改和写入授权状态。规则迁移或范围变化时，同时检查原适用范围与新适用范围。
3. 必要修复已在授权范围内时，将父规则与关联文档作为一组变更处理；需要修改范围外文档时，先暂停该组变更，报告准确文件和影响并进入范围扩张检查，不先写入父规则留下已知失效引用或无效覆盖。
4. 写入后重新读取所有目标文档及受影响的子级、引用文档，确认引用和覆盖均匹配当前规则；明确记录未能读取或验证的区域，不宣称关联文档已全部有效。

## 根级与模块级文档

### 根级文档

根级 `CONVENTIONS.md` 维护仓库地图、跨模块边界、共享工作流、公共命令、生成物和工程文档权威关系。

根级 `AGENTS.md` 是代理第一入口，必须包含模块路由，使代理能找到目标目录的局部文档；不要复制所有根级规则。

### 模块级文档

模块级 `CONVENTIONS.md` 只写本模块独有的职责、公共契约、扩展、覆盖和验证方式。不要重复父级规则，除非简短提醒能防止高代价错误。

模块级 `AGENTS.md` 只写规则读取链、有来源的模块职责和局部执行提醒。长期规则需要变化时，修改其权威文档，并在入口中引用；必要权威文档不在写入授权范围内时，先报告所需联动范围。

## 模板选择

| 目标 | 模板 |
| --- | --- |
| 根级长期规则 | `assets/根级.CONVENTIONS.template.md` |
| 模块级长期规则 | `assets/模块.CONVENTIONS.template.md` |
| 根级代理入口 | `assets/根级.AGENTS.template.md` |
| 模块级代理入口 | `assets/模块.AGENTS.template.md` |

模板中的章节按证据选用。没有覆盖时明确写“无”，不要制造虚假覆盖；不适用章节直接删除。
