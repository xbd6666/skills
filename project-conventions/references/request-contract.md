# 请求契约

## 初步记录与最终解析

开始发现前，先记录用户已经明确的值；使用“待发现”标记需要仓库证据才能确定的字段。不要在尚未检查仓库时假装已经解析“自动”或“匹配仓库”。

发现完成后，再最终解析：

| 字段 | 可选值 | 默认值 |
| --- | --- | --- |
| 工作方式 | `检查现有约定`、`制定约定方案`、`创建或更新约定` | 用户只要求分析、检查或找问题时为`检查现有约定`；其他未明确写入请求为`制定约定方案` |
| 范围 | 仓库根目录、明确模块路径、自动 | 自动 |
| 布局 | 仅根目录、根目录加模块、仅模块、自动 | 自动 |
| 已有文档策略 | 保留、更新、替换 | 保留 |
| 报告语言 | 用户指定语言、当前交流语言 | 当前交流语言 |
| 目标文档语言 | 按文件指定、保留原文、匹配目标范围 | 更新保留原文；新建匹配目标范围 |
| 验证授权 | 默认只读、已授权的具体验证动作及边界 | 默认只读；复用当前会话已有授权 |

上表中文名称用于说明契约语义。面向用户的报告按报告语言展示对应名称和值，不改变工作方式或策略含义；文件名、路径、命令和代码标识符保持原文。

报告语言不触发文档翻译。更新默认保留各目标文档的现有语言及有意保留的多语言结构；新建先沿用目标模块的语言约定，再参考适用的上级或仓库文档，仍无依据时使用当前交流语言。仅在不同选择会实质影响交付且无法据此确定时询问。用户已明确要求翻译或指定文档语言时按其范围执行；存在不同语言时按目标路径记录，不用一个全局值覆盖全部文件。旧请求中的“输出语言”按其明确指向的报告或文档解释，未限定对象时只约束报告。

## 工作方式判定

### 检查现有约定

用户要求检查、审查、诊断、比较、找问题、找冲突、判断是否需要调整或报告现状时使用。

- 检查现有约定文档及其与仓库证据的关系，默认只读；需要动态证据时按验证授权执行。
- 输出问题、严重度、证据、影响、建议和未决事项。
- 不创建隐含的约定文档写入承诺；验证权限按下文独立核对。

### 制定约定方案

用户要求设计布局、给出建议、规划约定文档或询问“应该怎么写”，但没有要求落盘时使用。

- 输出发现报告、推荐布局、精确文件清单和变更摘要。
- 明确说明本轮没有创建或更新约定文档；已授权验证的产物单独列明。
- 约定方案本身不转化为后续写入授权。

### 创建或更新约定

用户明确要求创建、生成、更新、写入、保存约定文档，或明确确认了上一轮可唯一识别的约定方案时使用。

- 用户要求更新既有文档时，已有文档策略解析为“更新”。
- 只有用户明确要求重写或替换指定文档时，策略才可解析为“替换”。
- “保留”意味着不改现有约定文档，只创建已解析范围中缺失的文档。
- “更新”意味着保持现有语气和结构，只做证据支持的最小修改。
- “替换”只重写用户明确点名的文件。

文档写入授权与候选规则采纳分别记录，采纳条件见 [discovery.md](discovery.md)。确认一份明确列出拟采纳候选及其适用范围的方案，可以同时授权写入和批量采纳；仅确认文件范围或要求生成文档，不视为采纳尚未确认的候选。

## 范围扩张检查

即使已经进入`创建或更新约定`，出现以下任一情况，也要按下文“暂停与部分交付”确定受影响组，对尚未覆盖的范围或决定给出准确方案并请求聚焦确认：

- 自动布局会在用户点名范围之外新增模块级文档；
- 计划跨越尚未获准的独立应用、包或所有权区域；
- 需要替换未被用户明确点名的既有文档；
- 父规则变更需要联动修复尚未获准修改的子级或引用文档；
- 目标文件存在无法归属的工作区修改；
- 文档冲突会实质改变权限、数据、安全、公共契约或验证结论；
- 需要改变尚未获准迁移的文档权威关系或转移规则主题；
- 无法确定仓库根、目标范围或目标文档语言，而不同选择会产生明显不同结果。

用户已经明确点名范围和文件时，不额外制造重复确认。

## 暂停与部分交付

暂停的最小单位是关联变更组：为使同一规则、权威关系、继承或引用保持有效而必须一起完成的修改。遇到冲突、授权缺口或无法归属的重叠修改时，该组保持原状并列出待确认方案；不先写入其中一部分留下已知不一致。

已获授权且不依赖该组的修改可以继续，仍以`创建或更新约定`交付，分别报告已完成组、未写入组及原因。同一文件中的独立条款也可分别处理，但须能保留受阻原文且不改变其依据或适用边界；不能可靠分离时将整个文件纳入该组。未采纳候选本身不阻塞独立的已确认规则。

只有仓库根、整体授权、共享权威关系等未决事项影响全部拟议修改，或所有修改均无法与受阻内容分离时，才停止整轮写入并以方案交付。没有冲突的组不因其他组等待确认而重复请求授权。

## 授权边界

约定文档写入授权不包含：

- 生产代码或测试代码修改；
- 格式化整个仓库、代码生成、依赖恢复或构建产物写入；
- 分支、提交、推送、合并或发布；
- 数据库查询或写入、迁移执行；
- 真实外部服务、爬虫、供应商或部署环境调用。

需要这些动作时，先核对当前会话已有授权；未覆盖的部分说明具体范围和副作用后再取得授权，已经覆盖的部分不重复询问。

## 验证授权与工作方式

验证权限与工作方式独立。检查或方案可以包含已授权的构建、测试或探测，仍以原工作方式交付，不因此获得约定或业务文件的修改权限。

执行前核对具体命令、目标环境、输入与产物位置，以及实际副作用是否已被当前请求或会话既有授权覆盖。命令包含多个副作用时均须覆盖；不能把某一验证动作的授权扩张为其他命令或整个环境的操作权限。

默认只读时只做静态发现。验证授权不足则继续可完成的静态检查，报告未执行部分及影响；确需补充授权时给出具体动作和副作用。已授权验证的命令、工作目录、产物、结果和证据边界与约定文档变更分别记录。
