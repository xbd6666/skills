# 行为场景回归

本目录用于维护本技能，常规仓库约定任务不需要读取。[behavior-cases.json](behavior-cases.json) 保存可独立复现的请求、最小文件内容和行为判据；`covers` 对应同文件 `topics` 中的主题编号，无需查阅历史对话。

## 使用方式

1. 根据本次变更选择相关场景。继承、候选采纳、文档权威或验证权限发生变化时，同时核对可能受影响的已有场景。
2. 静态审阅可直接对照输入与判据推演。需要实际执行时，在独立临时仓库中按 `files` 的相对路径准备文件；每个场景使用新的目录，不向真实项目复制场景文件。
3. 实际重放只向执行者提供待测技能、`conversation`（若有）、`request` 和原始文件，不提供场景名称、覆盖编号、`expected_outcomes` 或 `forbidden_outcomes`。需要解释器的场景先准备相应环境；不能执行时记录环境阻塞。
4. 用实际回答、文件差异、工具记录、命令和产物检查判据。判断语义与行为，不匹配固定标题、措辞或正则表达式。

涉及多项规则时优先重放组合场景：C13–C14 检查父子 AGENTS 摘要与独立护栏，C15–C16 检查三级继承，C17 检查受阻组与独立交付，C18 检查全范围发现，C19–C21 检查无父约定、未来路径与不同文档语言。原有 C01–C12 继续验证扩展、重命名、采纳、权威和验证权限，不能以新增场景代替旧行为。

场景中的命令仅在该场景授权范围内执行。C08 允许在临时仓库生成指定探测文件；C09 使用同一脚本但没有该授权。不得将一例的权限沿用到另一例，也不因回归需要访问真实外部服务或部署环境。

## 结果记录

逐例记录：场景编号、待测技能版本或差异、验证方式（静态审阅或实际重放）、关键观察及证据、未覆盖行为、结论。实际重放可记为通过、失败或环境阻塞；未重放时明确记录“未重放”，不填写通过。

JSON 结构检查、脚本语法检查和人工推演只能证明对应静态性质，不能作为模型行为回归通过的证据。场景判据应与已确认规则同步维护，不为迁就一次输出而放宽判据。

## 交付完整性

规则、模板和本目录的回归资料作为同一交付单元维护。准备 Git 交付时，在包含 `project-conventions/` 的仓库根检查这两个文件已纳入拟提交清单：

```text
git ls-files --error-unmatch -- project-conventions/tests/README.md project-conventions/tests/behavior-cases.json
```

该命令只证明 Git 索引包含文件，不证明已提交或发布。提交或打包后还须从实际交付的提交或包中核对 SKILL 的本地链接、两个回归文件及其内容版本；不能只检查工作区中的文件存在。已有暂存内容按原状态保留，提交和推送仍需相应授权。
